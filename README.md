# Second Brain

Трекер задач, который держит обязательства вместо вас. Не «Trello с напоминалками»: доска здесь отвечает на вопрос «что я делаю сейчас», а не «что я когда-то задумал», а агент раз в сутки смотрит на состояние и говорит, что с этим делать.

Локальный запуск, без облака. Готов к переезду на VDS: конфиг через env, никаких абсолютных путей, миграции идемпотентные.

---

## Что уже работает

**Навигация вперёд-назад.** Карточка — часть адреса (`?card=…`), поэтому кнопка «назад» в браузере её закрывает, «вперёд» — снова открывает. На узких экранах сайдбар не исчезает, а выезжает по кнопке меню сверху; в шторке карточки есть стрелка назад.

**Светлая и тёмная тема.** Переключатель — внизу сайдбара. По умолчанию берётся системная настройка, выбор запоминается в браузере и применяется до первой отрисовки, без вспышки. Всё оформление идёт через токены, так что тёмная — не инверсия фильтром, а своя палитра. Принудительно: `?theme=dark` или `?theme=light` в адресе.

**Доска в двух режимах.** «Горизонты» (Входящие → Сегодня → На неделе → Когда-нибудь → Готово) и «Этапы» (Не начато → В работе → Ждёт → Готово). Это не два разных канбана, а две проекции: у карточки независимо живут `horizon` (когда я собираюсь) и `stage` (в каком состоянии работа). Перетаскивание меняет только то поле, по которому сгруппировано.

**Сегодня — дневное обязательство, а не статус.** В 00:05 всё незакрытое возвращается на неделю с событием `rollover`, а не копится в «Сегодня» месяцами.

**Перенос — событие, а не правка даты.** Каждый сдвиг вправо пишется в журнал с причиной (нет времени / не хочу / не знаю как / жду другого). С третьего переноса карточка сама попадает в «Требует решения» на дашборде.

**Третий перенос требует решения.** Дальше система не двигает карточку молча: и потащить на доске, и нажать «отложить» — значит получить диалог с тремя выходами: разбить на шаг в 15 минут, поставить в конкретное время, или честно решить не делать. «Всё равно перенести» остаётся, но пишется в историю. Правило живёт на сервере (409 `escalation_required`), поэтому его нельзя обойти ни drag&drop, ни прямым запросом.

**Ресерч-карточки.** Тип «изучить» со своей схемой: вид (статья / видео / книга / тема), ссылка, «зачем» (какое решение разблокирует), мой вывод, статус (не смотрел → посмотрел → есть вывод → применено). Агент готовит разбор с вердиктом и следующим шагом на 15 минут — его можно принять или отклонить.

**Заметки с авторством.** Блоки «мои» и «агента» разделены, агент не перезаписывает ваш текст. Предложения агента приходят с кнопками «Принять / Убрать».

**Чек-лист внутри карточки** и подзадачи отдельными карточками. Первый пункт — не длиннее 15 минут.

**Входящие.** Захват ссылки или мысли одной строкой: ссылка становится материалом, текст с глаголом действия — задачей. Разбор вручную (Сегодня / Неделя / ✕) или кнопкой «Разобрать агентом».

**Агент.** Раз в сутки: чинит эмбеддинги, дотягивает ресерч, ищет дубли, отмечает залежавшееся, собирает бриф и один совет дня. Журнал прогонов — в `agent_runs`.

**Векторный поиск.** pgvector + локальные хеш-эмбеддинги по заголовку, «зачем», выводу и заметкам. Работает без ключей и сети; при появлении провайдера заменяется одна функция `embed()`.

## Стек

| | |
|---|---|
| Web | React 19, Vite, TypeScript, TanStack Query, dnd-kit, react-markdown |
| API | Fastify 5, TypeScript, node-cron, zod |
| БД | PostgreSQL 17 + pgvector |
| Агент | DeepSeek (`deepseek-flash`, text+image) — включается ключом |

```
apps/
  api/   Fastify + SQL (без ORM), миграции, сид, агент, джобы
  web/   интерфейс: дашборд, доска, входящие, шторка карточки
```

## Запуск

Нужен PostgreSQL 17 с расширениями `vector` и `pgcrypto` (Homebrew-сборка `postgresql@17` + `pgvector` подходит).

```bash
createdb secondbrain
cp .env.example .env
pnpm install
pnpm db:migrate
pnpm db:seed        # демо-данные: 4 области, 3 проекта, 24 карточки
pnpm dev
```

- интерфейс — http://localhost:5173
- API — http://127.0.0.1:4010

Полезное:

```bash
pnpm brief          # утренний бриф текстом (для launchd / cron / будущего Telegram)
pnpm db:reset       # сбросить схему и пересеять демо
pnpm build          # тайпчек и сборка
```

## Production и переезд на VDS

Один процесс отдаёт и API, и собранный фронт — один origin, без CORS и без отдельного nginx.

```bash
pnpm build
SERVE_WEB=1 API_HOST=0.0.0.0 API_PORT=4010 node apps/api/dist/index.js
```

Всё остальное — через env: `DATABASE_URL`, `API_HOST`, `SERVE_WEB`, `DEEPSEEK_API_KEY`, `TZ`.

**Обязательно для сервера:** задайте `AUTH_TOKEN`. Тогда каждая ручка `/api` требует `Authorization: Bearer <token>`, а интерфейс показывает экран входа и хранит токен только в браузере. Без `AUTH_TOKEN` API открыт — это нормально для localhost и недопустимо на VDS.

Для сервера есть `Dockerfile` и `docker-compose.yml` (образ `pgvector/pgvector:pg17`):

```bash
POSTGRES_PASSWORD=... AUTH_TOKEN=... docker compose up -d --build
docker compose run --rm app node apps/api/dist/seed.js   # демо-данные, по желанию
```

> Docker на этой машине не установлен, поэтому образ не собирался — файлы написаны, но проверьте их на VDS первым делом.

## Агент

Без `DEEPSEEK_API_KEY` приложение полностью работоспособно: совет дня считается правилами, ресерч не генерируется. С ключом включаются LLM-разбор карточек (пункт «Попросить агента изучить») и ночной ресерч.

Проводку к модели можно проверить без ключа — поднимается мок-эндпоинт и дергается настоящий код:

```bash
pnpm --filter @sb/api exec tsx src/agent/selfcheck.ts
```

Расписание (в `apps/api/src/jobs.ts`, таймзона из `TZ`):

- `00:05` — незакрытое «Сегодня» уезжает на неделю;
- `07:30` — прогон агента и бриф.

Пока всё локально, джобы работают только когда машина не спит. Для настоящих пушей нужен VDS и Telegram-бот — это следующий шаг, а не переделка.

## Бэкапы

```bash
./scripts/backup.sh                 # pg_dump в backups/
```

Один диск — одна ошибка. Поставьте скрипт в cron или launchd с первого дня.

## Модель данных

- `areas` — постоянные области жизни, `projects` — временные проекты с финишем.
- `cards` — заголовок, тип, `stage`, `horizon`, `state` (active / postponed / dropped), срок и слот, оценка, `postpone_count`, поля ресерча, эмбеддинг.
- `checklists`, `notes` (автор + вид), `attachments`, `events` (append-only журнал — источник правды для «перенос №3»), `briefs`, `agent_runs`, `settings`.
